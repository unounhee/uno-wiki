> **2단계에서 반드시 멈춰 승인을 받은 뒤 3단계로 간다. raw/ 파일은 어느 단계에서도 삭제·이동·본문 수정하지 않는다.**

- [x] **0단계. 안전장치** — 완료 (커밋 3d88d41 `구조: 정리 전 스냅샷`, CLAUDE.md 개정 + 이 체크리스트 포함, 푸시됨)
- [x] **1단계. index → log 이관** — index.md의 `raw/ (원문 — 불변)` 섹션을 log.md 상단 "원본 대장"으로 옮긴다. 형식: `날짜 | raw 파일 | 한 줄 요약 | 반영된 위키 페이지`. index.md에는 위키 페이지만 폴더별(core / ops-tutoring / ops-care-team / ops-shared / 루트)로 묶어 한 줄 요약과 함께 남긴다.
- [x] **2단계. 반영 점검 (여기서 멈춤)** — 대장 반영 열 채움, 점검 표 보고 완료. **운영자 승인 대기 중** (③ 파일명 처리 방식 포함) — raw 파일 각각에 대해 실제로 어느 위키 페이지에 반영됐는지 확인해 원본 대장의 "반영된 위키 페이지" 열을 채운다. 다음을 표로 보고: ①반영되지 않은 원본 ②원본과 위키가 어긋나는 부분(예: 분쟁 해결 한도 재설정, 관리팀 매출 연→월, 6~7할) ③파일명 날짜가 실제 구술일과 다른 raw 파일 목록. ③의 이름 변경 여부는 운영자가 결정 — 파일이 많으면 이름은 두고 원본 대장에 실제 구술일을 기록하는 쪽을 제안. **승인 전에는 어떤 위키 페이지도 고치지 않는다.**
- [x] **3단계. 실행 (승인 후)** — 완료: 대장 날짜 열을 실제 작성날짜로 교정(운영자 결정: 파일명 유지), 판단기준·사업전략에 변경 이력 섹션 신설(§5). 미반영 원본 0건·날짜/사건 표지 페이지 0건이라 흡수·삭제 작업 없음. — 반영되지 않은 원본을 해당 페이지에 흡수(core는 전문 제시·승인 후). 어긋난 수치는 CLAUDE.md §5대로 규칙 문서만 최신 수치로 통일하고 변경 이력을 남긴다. 위키 페이지 중 이름에 날짜·사건 표지가 있는 것은 해당 개념 페이지에 흡수·삭제 후 링크 수정. 끝나면 log.md 작업 장부에 기록하고 `개편: index 정리·원본 대장 도입` 커밋.
